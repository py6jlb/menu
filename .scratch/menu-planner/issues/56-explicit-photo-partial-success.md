# 56: Явный частичный успех сохранения рецепта и фото

**What to build:** Пользователь сохраняет одну зафиксированную версию рецепта и действия с фото. Если текст уже сохранён, а фото нет, он видит честный частичный результат и повторяет только действие с фото, не создавая второй рецепт.

**Blocked by:** 54 — Черновик рецепта с правильной идентичностью и защитой от потери.

**Status:** resolved (ticket/56-explicit-photo-partial-success; commits d6bac15, 03626a3)

- [x] В начале submit фиксируются ID/данные рецепта и одно действие с фото: оставить, загрузить/заменить либо удалить.
- [x] Изменение формы во время submit либо явно блокируется, либо сохраняется новым dirty-черновиком; позднее выбранное фото не подменяет отправленное действие.
- [x] При успешном тексте и сбое загрузки/удаления фото показано русское сообщение о частичном успехе, а не только запись в console.
- [x] Пользователь может повторить только фото-действие для уже сохранённого рецепта; повтор не вызывает создание нового рецепта или лишнюю перезапись полей.
- [x] Сохранённые поля и несохранённое фото различаются в состоянии черновика; переход после частичного успеха не уничтожает файл без понятного выбора пользователя.
- [x] При неизвестном результате фото-запроса сначала проверяется актуальное фото либо используется защищённое повторение, а не слепой автоматический повтор.
- [x] Ограничения размера/типа показываются до отправки; серверная валидация остаётся окончательной.
- [x] Проверены HTTP-отказ, обрыв сети, удаление фото, повтор загрузки и изменение выбора во время сохранения; pending всегда завершается.

## Evidence

- `photoIntentFromDraft` фиксирует в начале `save()` одно действие с фото (`keep`/`upload`/`delete`) вместе с id и телом; `keep` не отправляет фото-запрос — устранён прежний ложный PUT с пустым файлом. Intent захватывается до первого `await`, поэтому поздний выбор файла не подменяет отправленное действие.
- Поздние правки остаются новым dirty-черновиком: `applySavedText`/`applySavedPhoto` заменяют серверную часть, сохраняя более новый текст и поздний выбор файла; снятие позднего выбора возвращает черновик к подтверждённому виду (подтягивается актуальный `existing`).
- Частичный успех: `photoPartial` + русский `PHOTO_ERROR_MESSAGE` («Рецепт сохранён, но фото не удалось сохранить. Повторите действие с фото.») выводятся в `RecipeFormView`; кнопка «Повторить фото»/«Проверить и повторить».
- Повтор только фото: `retryPhoto()` использует замороженный `pendingPhoto` (id/ревизия/файл). Повторное «Сохранить» при неизменном тексте идёт ранней веткой по `textSignature` и не перезаписывает поля. Новый рецепт привязывается к своему id — второй не создаётся.
- Неизвестный результат (обрыв/неразобранный ответ): `photoUnknown` + `PHOTO_UNKNOWN_MESSAGE`; `verifyPendingPhoto` перечитывает рецепт — удаление однозначно видно по отсутствию фото (повтор не нужен), загрузка обновляет ожидаемую ревизию и повторяет идемпотентный PUT (без слепого дубля по старой версии). Известный HTTP-отказ повторяется без перечитывания.
- Identity фото: `isCurrentPhoto` отбрасывает поздний ответ фото после `setIdentity`, поэтому чужой ресурс не подменяется; успешное фото поднимает `revision` (для DELETE без тела — ровно на шаг), чтобы следующее сохранение не конфликтовало.
- Ограничения до отправки: `constants/recipe.js` (`PHOTO_TYPES`/`PHOTO_MAX_BYTES`/`validatePhotoFile`) и подсказка в форме; серверная валидация остаётся окончательной.
- Тесты: `useRecipeDraft.test.js` (44) — keep/upload/delete, частичный успех, повтор без второго рецепта и без перезаписи, HTTP-отказ против обрыва, защищённый повтор, изменение выбора во время сохранения, смена ресурса, dirty/предупреждение об уходе, ревизия; `constants/recipe.test.js` (4) — тип/размер.
