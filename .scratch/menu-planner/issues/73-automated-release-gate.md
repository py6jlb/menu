# 73: Автоматический гейт перед публикацией релиза

**What to build:** Разработчик получает автоматический проверяемый результат готовности релиза: публикация допускается только после проверок кода, реальной БД, поведения frontend и инфраструктурной конфигурации, а не после одной успешной сборки.

**Blocked by:** 37 — Проверка критических гарантий на PostgreSQL; 38 — Воспроизводимый и однозначно идентифицируемый релиз; 52 — Недельный черновик, устойчивый к поздним ответам и сетевым ошибкам.

**Status:** resolved (commits 04a6604, ed27407)

Гейт — `scripts/release-gate.sh`; запуск деплоя — `deploy/build-push.sh`; CI — `.github/workflows/release-gate.yml`; тесты — `deploy/tests/test_gate.py`; политика findings — `deploy/README.md`; решение — ADR-0013.

- [x] Автоматизированы быстрые backend-тесты, PostgreSQL critical-suite, drift-guard миграций, frontend state-тесты и чистая release-сборка из lockfile.
- [x] Гейт проверяет shell-инструменты (`bash -n` + shellcheck), семантику конфигурации (deploy-suite), Compose (`docker compose config` dev/prod), Caddy (`caddy validate`) и Collector (`validate`); один `bash -n` недостаточен.
- [x] Малый browser smoke проходит регистрацию/подтверждение через UI, создание семьи/рецепта, план и покупки, анонимный просмотр ссылки, а также `warning` (после перегенерации ссылки) и `broken` (после удаления источника) у второго пользователя, без изменения принятой семантики.
- [x] Этапы соответствуют текущим сценариям; перечень этапов и `--only/--skip` легко включают новые регрессии, не требуя всего набора 36–72.
- [x] Публикация (`build-push.sh --publish`) запускается только после зелёного гейта и browser smoke; обычная проверка не требует production-секретов, не деплоит сервер и не публикует образы.
- [x] Намеренная SQL-ошибка проваливает `postgres`, frontend-гонка — `frontend`, неверная инфраструктурная конфигурация — `infra`, каждый с понятной диагностикой (`GateFailureDiagnosticsTests`, `InfraCheckerTests`).
- [x] Тесты используют управляемые ответы, изолированные временные репозитории и подменённый `docker`; browser smoke берёт код подтверждения из журнала backend (без случайных пауз и неопределённых sleep), `trap` очищает контейнеры/volumes/временные файлы.
- [x] Диагностика доступна (`deploy/gate-artifacts/`, `summary.txt`) и не печатает письма/секреты; анализ зависимостей сообщает конкретные findings (пакет/образ, серьёзность, ссылка) и документированную политику обработки (report-only по умолчанию, `GATE_AUDIT_ENFORCE=1`).
- [x] CI — GitHub Actions (хостинг репозитория — GitHub): job гейта на push/PR, job публикации через `needs` только по тегу; локально те же проверки воспроизводятся `scripts/release-gate.sh` без SDK на хосте (только Docker).
