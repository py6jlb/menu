# 70: Повторяемость при подборе для выбранной недели

**What to build:** Участник выбирает блюдо и видит реально рассчитанную повторяемость относительно планируемой недели и личного окна, понимая, что показатель считает различные недели с рецептом, а не число записей одного дня.

**Blocked by:** 61 — Подбор доступных блюд с актуальными фильтрами и поиском.

**Status:** ready-for-agent

- [ ] Сохранена утверждённая семантика: количество различных недель, в которых присутствует локальный рецепт; повторения в нескольких записях одной недели дают один вклад.
- [ ] Окно из N недель заканчивается выбранным понедельником включительно, а не текущей неделей сервера; начало равно выбранной неделе минус N−1 недель.
- [ ] Используется личная настройка окна; данные ограничены семьёй, показатель вычисляемый и не превращается в хранимый счётчик.
- [ ] Подбор передаёт нужную неделю и возвращает действительный показатель; frontend сохраняет его при преобразовании выдачи и отображает объяснение, а не отсутствующее поле.
- [ ] Внешний рецепт сохраняет локальную identity подсчёта; копии/другие рецепты не объединяются по имени или источнику без отдельного решения.
- [ ] Показатель опирается на сохранённые планы, незаписанный черновик не выдаётся за уже учтённую историю; мягкие предпочтения автоматически не изменяются.
- [ ] Согласованы словарь, пользовательские подписи и описания решений; двусмысленное «сколько раз готовился» уточнено.
- [ ] Проверены выбранная прошлая/будущая неделя, границы окна, несколько записей одной недели, личная настройка, external и семейная изоляция.
