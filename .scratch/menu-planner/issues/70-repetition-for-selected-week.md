# 70: Повторяемость при подборе для выбранной недели

**What to build:** Участник выбирает блюдо и видит реально рассчитанную повторяемость относительно планируемой недели и личного окна, понимая, что показатель считает различные недели с рецептом, а не число записей одного дня.

**Blocked by:** 61 — Подбор доступных блюд с актуальными фильтрами и поиском.

**Status:** resolved (ticket/70-repetition-for-selected-week; commits d2ca78b)

- [x] Сохранена утверждённая семантика: количество различных недель, в которых присутствует локальный рецепт; повторения в нескольких записях одной недели дают один вклад.
- [x] Окно из N недель заканчивается выбранным понедельником включительно, а не текущей неделей сервера; начало равно выбранной неделе минус N−1 недель.
- [x] Используется личная настройка окна; данные ограничены семьёй, показатель вычисляемый и не превращается в хранимый счётчик.
- [x] Подбор передаёт нужную неделю и возвращает действительный показатель; frontend сохраняет его при преобразовании выдачи и отображает объяснение, а не отсутствующее поле.
- [x] Внешний рецепт сохраняет локальную identity подсчёта; копии/другие рецепты не объединяются по имени или источнику без отдельного решения.
- [x] Показатель опирается на сохранённые планы, незаписанный черновик не выдаётся за уже учтённую историю; мягкие предпочтения автоматически не изменяются.
- [x] Согласованы словарь, пользовательские подписи и описания решений; двусмысленное «сколько раз готовился» уточнено.
- [x] Проверены выбранная прошлая/будущая неделя, границы окна, несколько записей одной недели, личная настройка, external и семейная изоляция.

## Evidence

- **Окно по выбранной неделе.** Чистое правило `RepetitionRules.WeekStart(DateOnly)` сводит любую дату к понедельнику, `Window(selectedWeekStart, weeks)` заканчивает окно выбранной неделей включительно (начало — минус N−1 недель), `CurrentWeekStart` теперь делегирует `WeekStart`. Тесты `RepetitionRulesTests` (3) проверяют нормализацию середины недели и обе границы окна.
- **Счётчик.** `RepetitionCounter.CountForUserAsync(userId, familyId, weekStart?, ct)` учитывает личное окно из `UserSettings`, считает различные недели (`PlanEntries.Distinct(RecipeId, WeekPlanId)` → `GroupBy(RecipeId)`) и ограничивает выборку семьёй. Без `weekStart` якорь — текущая неделя (список/деталь/repetition не изменились). `CountWindowForUserAsync` отдаёт показатель вместе с размером окна, чтобы подбор не читал настройки дважды.
- **Контракт подбора.** `RecipeMatchRequest.WeekStart` (понедельник недели), `RecipeMatchItemDto.RepetitionCount` (число разных недель до выбранной включительно) и `RecipeMatchResponse.RepetitionWindowWeeks`. Показатель считается по локальному `RecipeId`, поэтому внешний рецепт сохраняет identity обёртки, а копии/другие рецепты не сливаются по имени или источнику. Мягкие предпочтения не меняются, черновик клиента в планах не хранится.
- **Frontend.** `useRecipePicker` передаёт `weekStart` в тело подбора (сохраняется между фильтрами), `toPickerItem` переносит `repetitionCount` (отсутствие → 0), `repetitionWindowWeeks` берётся из ответа и сбрасывается при ошибке. `PlanView` открывает подбор с `toIso(monday)`, показывает чип и пояснение до выбранной недели.
- **Словарь.** `constants/repetition.js` держит подписи: чип «🔁 N нед.», пояснение «разных неделях … один раз» и текст окна подбора. `RecipesView`, `RecipeBody`, `PlanView`, `SettingsView` больше не говорят «сколько раз готовилось»; `CONTEXT.md` и ADR-0004 уточняют определение (различные недели, окно до выбранной/текущей).
- **Тесты backend (fast):** `docker run … dotnet test` → Failed: 0, Passed: 557, Skipped: 61. Новые: `RepetitionRulesTests`, `RepetitionFlowTests` (выбранная будущая/прошлая неделя, границы окна, несколько записей одной недели, личное окно 1 и окно в ответе, отсутствие плана, чужая семья), `ExternalRecipeIntegrationFlowTests.Match_Repetition_CountsExternalByLocalIdentity`.
- **Тесты backend (PostgreSQL):** `scripts/test-postgres.sh` → Failed: 0, Passed: 66.
- **Тесты frontend:** `npm test` → 222 passed (`useRecipePicker` — 22, включая передачу недели, перенос показателя, окно и сброс окна при ошибке; `constants/repetition` — 3), `npm run build` — успешно.
- **Ревью.** Двухосевое ревью: убрано двойное чтение настроек в подборе (показатель и окно — одним вызовом), helper теста делегирует общему, добавлен тест выбранной прошлой недели с исключением более поздних, определение повторяемости синхронизировано с CONTEXT/ADR.
