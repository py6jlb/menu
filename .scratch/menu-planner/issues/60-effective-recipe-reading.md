# 60: Единое актуальное чтение рецепта для списка и деталей

**What to build:** Участник видит в списке и подробном рецепте согласованные актуальные данные, источник и состояние ссылки. Чтение краткого списка не загружает все шаги и ингредиенты каждого источника.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Предметный модуль чтения скрывает связь локального рецепта с источником, доступность и происхождение; потребители не собирают эти правила самостоятельно из нескольких resolver.
- [ ] Список и подробная страница используют модуль; локальный ID и семейная принадлежность не заменяются ID/владением источника.
- [ ] Summary и detail загружают нужную проекцию: имя/метаданные не требуют двух полных дочерних коллекций; нет запроса на каждый внешний рецепт отдельно.
- [ ] Состояние и контент согласованы при удалении/изменении источника, недоступность не выглядит полноценным рецептом с нулевыми параметрами.
- [ ] Изменения источника видны при повторном чтении; кэш имени и broken fallback сохраняют текущие предметные правила.
- [ ] Warning остаётся читаемым, broken оставляет кэш имени без выдуманного контента; происхождение копии и запрет транзитивного sharing не меняются.
- [ ] Публичный просмотр, существующие контракты и остальные потребители продолжают работать: расширение выполнено совместимо для последующей миграции сценариев.
- [ ] Проверены обычный/external/warning/broken, чужая семья и удаление источника между действиями; записан baseline SQL-count/объёма для списка и деталей.
- [ ] Рефакторинг не вводит универсальный repository/CQRS: модуль скрывает реальные гарантии чтения, а не только переадресует вызовы.
