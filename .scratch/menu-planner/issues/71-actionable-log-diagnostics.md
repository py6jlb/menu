# 71: Рабочая диагностика по релизу и trace-id

**What to build:** Оператор находит ошибку и связанные события запроса по trace-id и версии релиза, а временный отказ Collector не блокирует приложение. Журналы содержат полезную диагностику без секретных кодов и токенов.

**Blocked by:** None (can start immediately)

**Status:** resolved (commits 03ab2ba, 1d381de)

- [x] Экспорт соответствует настроенным pipelines: до появления согласованного хранения полных traces их экспорт отключён, Activity/trace-id для логов сохранены.
- [x] Структурированные события содержат operation, trace-id и доступный release-id; отсутствие manifest не ломает приложение и отображается явно.
- [x] Коды подтверждения/сброса, credentials, JWT и share-токены не попадают в логи/URL access-логов; исключения и запросы не раскрывают полное письмо.
- [x] Collector реально записывает в volume с правильными правами; restart сохраняет журналы, rotation проверена по размеру/count и документированному фактическому окну.
- [x] Недоступность Collector имеет ограниченную буферизацию/поведение потери и не блокирует обработку пользовательского запроса или неограниченно растит память.
- [x] Добавлена минимальная пригодная диагностика края, если нужна для корреляции публичных отказов, с теми же правилами минимизации секретных URL.
- [x] Контрольная запись после запроса находится по trace-id, проверены restart, rotation, отказ Collector и восстановление; полный APM/дашборды не являются условием выполнения.
