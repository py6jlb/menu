# 53: Конфликты совместного сохранения плана на неделю

**What to build:** Два участника семьи сохраняют недельный план с контролем версии: устаревшая попытка не перезаписывает чужую работу и не смешивает записи, а пользователь сохраняет свой черновик и понимает, как продолжить.

**Blocked by:** 37 — Проверка критических гарантий на PostgreSQL; 52 — Недельный черновик, устойчивый к поздним ответам и сетевым ошибкам.

**Status:** ready-for-agent

- [ ] План имеет ревизию всей недели; чтение передаёт её, сохранение проверяет ожидаемую ревизию атомарно вместе с полной заменой записей.
- [ ] Два PUT от одной ревизии дают один успех и один согласованный конфликт; итог не является объединением двух полных запросов.
- [ ] Первое конкурентное создание недели обработано при уникальности семьи/даты; отсутствие плана имеет ясную исходную ревизию/условие создания.
- [ ] Удаление и пересечение PUT/DELETE также защищают изменение недели; существующий контракт не теряет идемпотентность повторного удаления без новых данных.
- [ ] При конфликте UI оставляет локальный черновик, показывает актуальность серверной версии и предлагает безопасную перезагрузку/сравнение без автоматического overwrite.
- [ ] Успех относится к отправленной ревизии и snapshot; ошибки сети не снимают защиту от неизвестного исхода сохранения.
- [ ] Миграция сохраняет существующие планы; границы семьи и валидация записей остаются действующими.
- [ ] На PostgreSQL проверены пустой существующий план с разными слотами, совпадающие слоты, первое создание и PUT/DELETE; frontend-регрессии проверяют сохранность черновика при конфликте.
