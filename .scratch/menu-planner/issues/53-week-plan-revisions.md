# 53: Конфликты совместного сохранения плана на неделю

**What to build:** Два участника семьи сохраняют недельный план с контролем версии: устаревшая попытка не перезаписывает чужую работу и не смешивает записи, а пользователь сохраняет свой черновик и понимает, как продолжить.

**Blocked by:** 37 — Проверка критических гарантий на PostgreSQL; 52 — Недельный черновик, устойчивый к поздним ответам и сетевым ошибкам.

**Status:** resolved (ticket/53-week-plan-revisions)

- [x] План имеет ревизию всей недели; чтение передаёт её, сохранение проверяет ожидаемую ревизию атомарно вместе с полной заменой записей.
- [x] Два PUT от одной ревизии дают один успех и один согласованный конфликт; итог не является объединением двух полных запросов.
- [x] Первое конкурентное создание недели обработано при уникальности семьи/даты; отсутствие плана имеет ясную исходную ревизию/условие создания.
- [x] Удаление и пересечение PUT/DELETE также защищают изменение недели; существующий контракт не теряет идемпотентность повторного удаления без новых данных.
- [x] При конфликте UI оставляет локальный черновик, показывает актуальность серверной версии и предлагает безопасную перезагрузку/сравнение без автоматического overwrite.
- [x] Успех относится к отправленной ревизии и snapshot; ошибки сети не снимают защиту от неизвестного исхода сохранения.
- [x] Миграция сохраняет существующие планы; границы семьи и валидация записей остаются действующими.
- [x] На PostgreSQL проверены пустой существующий план с разными слотами, совпадающие слоты, первое создание и PUT/DELETE; frontend-регрессии проверяют сохранность черновика при конфликте.

## Evidence

- Ревизия недели — `WeekPlan.Revision` (`int`, токен оптимистичной блокировки; у отсутствующего плана `0`). Атомарная замена записей и проверка ожидаемой ревизии вынесены в scoped-сервис `Plans/WeekPlanSaver.cs`; `PlanEndpoints` отдаёт `revision` в GET, принимает `expectedRevision` в PUT и `?expectedRevision=` в DELETE, конфликт — `409 { error, weekStart, revision, entries }` с текущей серверной версией.
- Миграция `20261006090857_AddWeekPlanRevision`: `Revision integer NOT NULL DEFAULT 0` — существующие планы сохраняются.
- Frontend: `useWeekDraft` ведёт `revision` и `conflict`; при `409` черновик и ревизия не трогаются, `reloadServerVersion()` после подтверждения заменяет черновик серверной версией; `PlanView.vue` показывает сообщение, серверную ревизию и кнопку загрузки.
- Тесты: `PlanFlowTests` (устаревшая ревизия, отсутствие плана с ненулевой ревизией, идемпотентное удаление, устаревшее/отсутствующее `expectedRevision`), `Postgres/PostgresWeekPlanRevisionTests` (пустой план с разными слотами, совпадающий слот, первое создание, конкурентные PUT и создание, PUT/DELETE, идемпотентный повтор удаления), `useWeekDraft.test.js` (+6).
