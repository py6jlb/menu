# 57: Восстановление после ошибок действий с семьёй

**What to build:** Пользователь исправляет неверный инвайт-код и повторяет вступление, а Владелец семьи продолжает работу после сбоя копирования кода или удаления участника. Ошибка действия не скрывает загруженную семью и формы.

**Blocked by:** 37 — Проверка критических гарантий на PostgreSQL.

**Status:** resolved (commit fc8deb6)

- [x] Ошибка первоначальной загрузки отделена от ошибок создания, вступления, clipboard, перегенерации и удаления; сообщения показаны у соответствующего действия.
- [x] После неверного инвайт-кода формы остаются доступны, значение можно исправить и повторить без перезагрузки страницы.
- [x] Ошибка clipboard не скрывает инвайт-код/семью; сбой удаления не исчезает из интерфейса вместе со списком участников.
- [x] Все сетевые операции завершают pending и допускают безопасный ручной повтор; двойные клики на мутации не создают конкурирующих одинаковых запросов.
- [x] Создание/вступление при гонке уникального членства возвращает ожидаемый конфликт вместо 500; пользователь не остаётся с ложным локальным состоянием.
- [x] Владелец, участник, неподтверждённая почта и чужая семья сохраняют действующие полномочия; изменение инвайт-кода не расширяет их.
- [x] Проверены сетевой отказ, неверный код, clipboard-отказ, двойной клик и гонка двух созданий/вступлений; SQL-ограничения проверены на PostgreSQL.

## Evidence

- Backend: операции с семьёй вынесены в scoped `FamilyService` (`backend/src/MenuPlanner.Api/Families/FamilyService.cs`), `FamilyEndpoints` стали тонкими. Гонка уникального членства (`FamilyMembers.UserId`) перехватывается на `DbUpdateException`, сущности отцепляются, и проигравший получает `409`, а не `500`; семья/членство в БД остаются в единственном экземпляре.
- Тесты backend (fast): `FamilyFlowTests` — перегенерация инвалидирует прежний код и не расширяет права участника, посторонний и неподтверждённый пользователи получают `403` на regenerate/remove. Все 406 проходят, 38 Postgres-тестов пропускаются без БД.
- Тесты backend (PostgreSQL): `Postgres/PostgresFamilyMembershipTests.cs` — детерминированная гонка двух созданий и двух вступлений через `AsyncBarrier` на команде вставки (без sleep): ровно один `Ok`, один `Conflict`, одна семья и одно членство. `scripts/test-postgres.sh` — 41 passed.
- Frontend: `frontend/src/composables/useFamily.js` ведёт отдельные `loadError`/`createError`/`joinError`/`copyError`/`regenerateError`/`removeError` и флаги ожидания, `finally` всегда снимает pending, защита от двойного клика. `FamilyView.vue` показывает сообщение у соответствующего действия, после неверного кода формы доступны, сбой clipboard/удаления не скрывает данные.
- Тесты frontend: `frontend/src/composables/useFamily.test.js` — 19 поведенческих (загрузка/повтор, create/join, clipboard-отказ и отсутствие clipboard, перегенерация, удаление, двойной клик). `npm test` — 70 passed, `npm run build` — успешно.
- Схема БД не менялась: `dotnet ef migrations has-pending-model-changes` — «No changes have been made to the model since the last migration».
- Ограничение: ошибка перезагрузки уже открытой семьи показывает экран восстановления с кнопкой «Повторить» (не входит в критерии тикета, где разделены именно первоначальная загрузка и действия).
