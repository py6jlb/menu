# 69: Настройки без побочных эффектов чтения

**What to build:** Пользователь читает значения личных настроек по умолчанию без создания записи, изменяет их предсказуемо и может повторить действие после сетевого сбоя или конфликтующего первого сохранения.

**Blocked by:** 37 — Проверка критических гарантий на PostgreSQL.

**Status:** resolved (ticket/69-side-effect-free-settings; commits bb3ad14, d2efce7)

- [x] GET отсутствующих настроек возвращает defaults и не записывает БД; повторное чтение не создаёт запись и не конфликтует с другим читателем.
- [x] Явное сохранение создаёт/обновляет настройки, обрабатывает конкурентную первую вставку при уникальности пользователя без необработанного 500.
- [x] Диапазон окна повторяемости и изоляция пользователя сохранены; неподтверждённая почта читает, но не меняет настройки.
- [x] UI отличает загрузку, изменение и сохранение; network/parsing failures завершают pending, сохраняют введённое и дают понятный повтор.
- [x] Ответ более старой операции не уничтожает последующую правку; подтверждённое сохранение отражает фактическое серверное значение.
- [x] Проверены отсутствующая запись, повторные GET без записи, два первых сохранения на PostgreSQL, валидация и отказ сети в интерфейсе.

## Evidence

- **Чтение без побочных эффектов.** Новый scoped-сервис `Settings/SettingsService.cs`: `ReadAsync` читает `AsNoTracking` и при отсутствии строки возвращает `SettingsCatalog.DefaultRepetitionWindowWeeks` без записи. Эндпоинт `GET /api/settings` больше не создаёт запись. Быстрые тесты `SettingsFlowTests` проверяют, что одиночный и повторные GET не создают строку (`UserSettings.Count == 0`), а Postgres-тест `PostgresSettingsTests.ReadMissing_DoesNotPersistDefault` подтверждает то же на настоящей БД.
- **Гонка первой вставки.** `SaveAsync` создаёт или обновляет строку; `catch (DbUpdateException) when inner is PostgresException { SqlState: UniqueViolation }` откатывает неудачную вставку и применяет значение к уже созданной строке. `PostgresSettingsTests.ConcurrentFirstSave_ResolvesToSingleRow_WithoutError` детерминированно сводит два сохранения на барьере (`BarrierNonQueryInterceptor` по `INSERT INTO "UserSettings"`): обе операции завершаются без 500, остаётся одна строка.
- **Границы и изоляция.** Валидация диапазона (`SettingsCatalog`, 1..52) и `RequireVerifiedEmail` на PUT сохранены; существующие `RepetitionFlowTests` (round-trip, невалидные значения, per-user) и `ReadOnlyUnverifiedTests` (GET разрешён, PUT 403) проходят без изменений.
- **UI.** `composables/useSettings.js`: состояния `loading`/`saving`/`dirty`, привязка ответов к номеру запроса, `finally` снимает pending, ошибка сети/разбора сохраняет ввод и допускает повтор. `SettingsView.vue` показывает раздельно загрузку, ошибку загрузки с кнопкой «Повторить», сохранение, несохранённые изменения и ошибку сохранения с «Повторить сохранение»; границы берутся из `constants/settings.js`. Тесты `useSettings.test.js` (10) и `constants/settings.test.js` (3) покрывают сетевой отказ, parsing, правку во время сохранения и устаревший ответ.
- **Ревью.** Двухосевое ревью: catch сужен до фактического уникального нарушения (не подавляет посторонние сбои БД), сообщение «сохранено» не показывается, если после отправки была новая правка, параметр сервиса переименован в `settingsService`.
- **Проверки.** `dotnet test` — Failed: 0, Passed: 546, Skipped: 61; `scripts/test-postgres.sh` — Failed: 0, Passed: 66; frontend `npm test` — 202 passed, `npm run build` — успешно.
