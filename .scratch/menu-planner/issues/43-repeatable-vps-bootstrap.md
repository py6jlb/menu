# 43: Повторяемая настройка сервера без потери административного доступа

**What to build:** Оператор может повторно выполнить настройку VPS и сохранить рабочий вход и административные полномочия. Старый доступ закрывается только после проверки нового, ошибочная конфигурация SSH не оставляет сервер недоступным.

**Blocked by:** None (can start immediately)

**Status:** claimed (ticket/43-repeatable-vps-bootstrap; ожидает code-review)

- [ ] Повторная настройка не затирает существующие разрешённые SSH-ключи; новый ключ добавляется предсказуемо без дублей.
- [ ] Определён рабочий способ административных действий созданного пользователя; наличие записи в группе sudo не считается достаточной проверкой.
- [ ] До применения SSH-настроек проверяются синтаксис и эффективная конфигурация, реальный listener и socket activation используемой Ubuntu.
- [ ] Закрытие старого порта выполняется отдельным явным шагом после подтверждения входа в другом сеансе; неверная конфигурация не закрывает работающий путь.
- [ ] Установка Docker использует проверяемый источник; наличие Compose v2 и работоспособность нужных инструментов подтверждены явно.
- [ ] Проверено реальное действие SSH-защиты на выбранном порту, а не только установка fail2ban.
- [ ] На чистой временной VM выполнены два последовательных прогона и сценарий неверного SSH-конфига; ключевой вход, административный путь и Compose работают.
- [ ] Документирован аварийный доступ через консоль провайдера без включения специфичных для одного провайдера зависимостей.
