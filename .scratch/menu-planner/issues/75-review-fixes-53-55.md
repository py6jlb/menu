**Blocked by:** None (can start immediately)

**Status:** resolved (commits 61654c6, merge 15b436c)

## Standards

- [x] `README.md` описывает `revision`/`409`/`400` для `PUT`/`DELETE`/`copy`/фото рецепта.
- [x] Убраны `static`-методы, принимающие `AppDbContext` (`PlanEndpoints.ConflictAsync`, `RecipeEndpoints.ConflictAsync`, `RevisionProblem`).
- [x] Запрос текущей ревизии рецепта вынесен в один scoped-сервис `RecipeRevisionReader`.
- [x] Путь чтения плана вынесен в scoped `WeekPlanReader`; GET/успех PUT/конфликт используют один проектор.
- [x] Операции фото идут через `RecipeMutationService` (одна защита ревизии).
- [x] `RecipeTarget` группирует `(Id, FamilyId)`; `revision` осознанно остаётся `int` — это токен конкурентности EF.
- [x] Обновление кэша имени внешнего рецепта — scoped `ExternalRecipeNameCache` с одной безопасной попыткой.

## Spec

- [x] `RecipeDetailView` показывает конфликт ревизии при удалении/локальном удалении/копировании и предлагает загрузить актуальную версию.
- [x] `RecipeFormView` при сбое фото после успешного сохранения текста показывает частичный результат и позволяет повторить только действие с фото.
- [x] `PlanView` при конфликте показывает построчное сравнение серверной и локальной версий, а не только число записей.
- [x] `DELETE /photo` без фото — no-op без роста ревизии.
- [x] Миграция ревизии недели проставляет существующим планам `Revision = 1`, не смешивая с sentinel `0`.
- [x] Кэш имени обновляется при каждом чтении (с повтором при гонке), а не молча пропускается.
