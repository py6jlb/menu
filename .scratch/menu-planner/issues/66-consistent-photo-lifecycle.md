# 66: Согласованный жизненный цикл файлов фото

**What to build:** Загрузка, замена, удаление и промоушен фото не оставляют БД и файловое хранилище в противоречии при сбое; пользователь получает результат фактической операции, а безопасная уборка удаляет только действительно бесхозные файлы.

**Blocked by:** 55 — Конкурентное редактирование и однократный промоушен в копию.

**Status:** ready-for-agent

- [ ] Жизненный цикл фото сосредоточен в предметном модуле, использует ревизию рецепта и явно согласует файл с DB-commit.
- [ ] Новый файл удаляется компенсацией при неуспехе записи БД; если компенсация сама неуспешна, файл остаётся диагностируемым кандидатом для уборки.
- [ ] Старый файл удаляется после commit повторяемой операцией; ошибка cleanup не возвращает ложный общий неуспех уже завершённого изменения рецепта.
- [ ] Параллельные замены, загрузка/удаление рецепта и copy/смена фото источника не удаляют актуальный файл и не создают незамеченных постоянных сирот.
- [ ] Уборка проверяет ссылки и безопасный возраст файлов, не трогает незавершённую загрузку/копирование или файлы, нужные текущему backup.
- [ ] Согласована сохранность старых файлов с backup-набором: новые правила не нарушают точку восстановления при одновременной замене фото.
- [ ] Существующая политика публичного URL сохранена: отзыв ссылки не объявляется отзывом ранее полученного URL фото; изменение приватности не входит в этот тикет.
- [ ] Проверены ошибка DB после записи файла, ошибка удаления после commit, конкурентные замены и промоушен; инспекция после cleanup подтверждает отсутствие потери актуальных фото.
