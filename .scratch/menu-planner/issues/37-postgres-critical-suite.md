# 37: Проверка критических гарантий на PostgreSQL

**What to build:** Разработчик получает воспроизводимую контейнерную проверку настоящих гарантий PostgreSQL рядом с быстрыми тестами: успешный результат подтверждает исполнение миграций и ограничений, а не только совпадение модели в памяти.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Узкий интеграционный набор работает с настоящей PostgreSQL той же основной версии, что и приложение, не затрагивая рабочие данные и dev-БД.
- [ ] Проверены миграция пустой БД штатным запуском и повторный запуск без изменения данных; проверка upgrade допускает добавление следующей миграции в последующих тикетах.
- [ ] Проверены уникальность членства пользователя, недели семьи, записи плана, ссылки на рецепт и внешнего рецепта на источник, включая частичный индекс.
- [ ] Проверены внешние ключи и каскадное удаление на представительном сценарии семьи, рецепта и записи плана.
- [ ] Проверен round-trip количества ингредиента и отказ на значениях вне текущего диапазона хранения; тесты не утверждают новую продуктовую точность вместо существующей.
- [ ] Предоставлен пригодный для последующих тикетов способ управляемо пересекать два независимых запроса/контекста; гонки не зависят от случайных задержек.
- [ ] Данные изолированы между проверками, временные ресурсы очищаются и после неуспеха; запуск документирован и не требует SDK на хосте.
- [ ] Быстрый suite сохранён; ADR о тестировании дополнен обоснованным исключением для критических PostgreSQL-проверок. Startup migrate, fail-fast и forward-only остаются действующими решениями.
