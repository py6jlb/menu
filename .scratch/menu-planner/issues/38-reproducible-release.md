# 38: Воспроизводимый и однозначно идентифицируемый релиз

**What to build:** Оператор выпускает и повторно запускает ровно выбранную версию приложения: происхождение образов известно, конфигурация соответствует релизу, а обычный перезапуск не переводит установку на случайный latest.

**Blocked by:** 36 — Единый безопасный формат конфигурации скриптов.

**Status:** resolved (commit 5772fb9, refactor 120b9e3)

Проверки — `deploy/tests/test_release.py`, запуск suite — `python3 -B -m unittest discover -s deploy/tests`; доказательства — `deploy/tests/README.md`, решение — ADR-0008 и `deploy/README.md`.

- [x] Релиз связывает commit, digests backend/frontend, версии конфигурации и время сборки; manifest сохраняется и доступен для диагностики и восстановления.
- [x] Незакоммиченные изменения не публикуются под идентификатором чистого commit: release-сборка отклоняет dirty checkout с понятной причиной.
- [x] Выбор релиза неизменяемый; latest может быть вспомогательным указателем, но не заменяет закреплённую версию. Предыдущая версия остаётся доступной для получения.
- [x] Выбранная версия сохраняется на сервере; повторный штатный запуск Compose использует её без временного экспорта в SSH-сессии.
- [x] Конфигурации берутся из выпускаемого среза; повторный деплой старого релиза не подмешивает новые локальные конфигурации.
- [x] Frontend использует поддерживаемую LTS Node и установку по lockfile; чистая установка не изменяет lockfile, гейт и контейнерная сборка используют согласованное окружение.
- [x] Базовые образы закреплены контролируемыми версиями/digests с документированным порядком обновления.
- [x] Отсутствующий статический asset возвращает 404, обычный прямой переход на маршрут SPA продолжает работать.
- [x] Smoke на стенде подтверждает повторный запуск выбранной версии и идентичность manifest; процедура сборки не публикует образы без явного запуска публикации.
