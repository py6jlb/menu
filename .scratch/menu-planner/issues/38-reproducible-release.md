# 38: Воспроизводимый и однозначно идентифицируемый релиз

**What to build:** Оператор выпускает и повторно запускает ровно выбранную версию приложения: происхождение образов известно, конфигурация соответствует релизу, а обычный перезапуск не переводит установку на случайный latest.

**Blocked by:** 36 — Единый безопасный формат конфигурации скриптов.

**Status:** claimed (ticket/38-reproducible-release; ожидает итогового code-review)

Реализация и изолированные проверки подготовлены в worktree; доказательства критериев и TDD red/green — `deploy/tests/README.md`. Чеклист оставлен для итогового ревью основным агентом.

- [ ] Релиз связывает commit, digests backend/frontend, версии конфигурации и время сборки; manifest сохраняется и доступен для диагностики и восстановления.
- [ ] Незакоммиченные изменения не публикуются под идентификатором чистого commit: release-сборка отклоняет dirty checkout с понятной причиной.
- [ ] Выбор релиза неизменяемый; latest может быть вспомогательным указателем, но не заменяет закреплённую версию. Предыдущая версия остаётся доступной для получения.
- [ ] Выбранная версия сохраняется на сервере; повторный штатный запуск Compose использует её без временного экспорта в SSH-сессии.
- [ ] Конфигурации берутся из выпускаемого среза; повторный деплой старого релиза не подмешивает новые локальные конфигурации.
- [ ] Frontend использует поддерживаемую LTS Node и установку по lockfile; чистая установка не изменяет lockfile, гейт и контейнерная сборка используют согласованное окружение.
- [ ] Базовые образы закреплены контролируемыми версиями/digests с документированным порядком обновления.
- [ ] Отсутствующий статический asset возвращает 404, обычный прямой переход на маршрут SPA продолжает работать.
- [ ] Smoke на стенде подтверждает повторный запуск выбранной версии и идентичность manifest; процедура сборки не публикует образы без явного запуска публикации.
