# 46: Атомарный сброс пароля без внешне навязанной блокировки

**What to build:** Пользователь восстанавливает доступ одним действующим кодом; смена пароля и отзыв старых токенов происходят целиком. Посторонний, знающий email, не может запросами без действующего кода навязать длительную блокировку восстановления.

**Blocked by:** 45 — Атомарное подтверждение почты и повторная выдача кода.

**Status:** ready-for-agent

- [ ] Сброс использует общий атомарный lifecycle кодов; выдача reset соблюдает cooldown, срок действия и единственный действующий challenge.
- [ ] Потребление кода, запись нового хэша пароля и изменение версии токенов составляют одну защищённую операцию.
- [ ] Два reset одним кодом не дают двух успешных смен; последовательные реальные смены корректно увеличивают версию, старые JWT перестают работать.
- [ ] Неверные попытки относятся к реально действующему challenge: отсутствие, истечение или уже потреблённый код не создают длительную блокировку аккаунта от анонимных запросов.
- [ ] Ограничение действующего перебора не ослаблено: превышение попыток закрывает конкретный challenge; после штатного cooldown пользователь может получить новый, без навязанного трёхдневного lockout восстановления.
- [ ] Подтверждение почты сохраняет своё согласованное правило блокировки; сброс не создаёт случайную общую блокировку разных операций. Административная разблокировка сохраняет понятный результат.
- [ ] Forgot сохраняет нейтральный ответ для неизвестного/неподтверждённого email; UI корректно показывает допустимость повторной выдачи и снимает pending при сбое.
- [ ] Проверены параллельное потребление, счётчик, resend и сценарий пяти запросов без challenge на PostgreSQL; семантика изменённых блокировок документирована.
