# 25: Шаринг рецептом по ссылке

**What to build:** Любой участник семьи-источника на детальной странице рецепта получает и копирует ссылку на рецепт. Владелец семьи может отозвать ссылку (запрет новых добавлений) или перегенерировать её (отзыв старой + новая). Одна запись `RecipeShare` на рецепт; URL вида `/r/{token}`.

**Blocked by:** None (can start immediately)

**Status:** resolved (commit 0eed76dabe954fd0436e95341fea0b57dda1a8d5)

- [x] Участник семьи открывает рецепт и видит блок «Поделиться» со ссылкой и кнопкой «Скопировать»
- [x] Первое «Поделиться» создаёт `RecipeShare` с токеном; повторный запрос возвращает ту же ссылку (одна ссылка на рецепт)
- [x] Участник другой семьи или неавторизованный не может получить ссылку (`403`/`401`); пользователь не из семьи-источника → `404`
- [x] Владелец семьи может «Отозвать» — ссылка мертва для новых добавлений; участник (не владелец) действий отзыва/перегенерации не видит и вызвать не может (`403`)
- [x] Владелец семьи может «Перегенерировать» — старая ссылка мертва, появляется новая действующая
- [x] Flow-тесты через `ApiFactory` (WebApplicationFactory + InMemory) покрывают генерацию, отзыв, перегенерацию и ошибки доступа
