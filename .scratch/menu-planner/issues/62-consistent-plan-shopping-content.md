# 62: Согласованные план и список покупок с диагностикой полноты

**What to build:** Семья видит одинаковое актуальное состояние блюда в плане и покупках; если продукты для части записей нельзя рассчитать, список честно сообщает об этом и позволяет перейти к замене блюда.

**Blocked by:** 60 — Единое актуальное чтение рецепта для списка и деталей.

**Status:** resolved (commits ea289d9, 1a613c2)

- [x] План и покупки получают контент/state из единого модуля; для имени плана не загружаются все шаги, для покупок запрашиваются нужные ингредиенты/порции.
- [x] Живые ингредиенты и servings источника используются для внешнего рецепта; warning продолжает участвовать в расчёте.
- [x] Broken исключён из сумм, но возвращается в диагностике полноты с указанием записи плана и причины; устаревшие ингредиенты не подставляются.
- [x] Экран покупок показывает предупреждение о неполном расчёте, перечень исключённых записей и переход к выбранной неделе для замены/удаления.
- [x] Отсутствующий план, пустой план и план только с недоступными блюдами различимы для пользователя; обычный пустой результат не маскирует потерю источников.
- [x] Количества, масштабирование, группировка единиц и отдельные бытовые меры сохраняют принятые правила без нового округления.
- [x] Загрузка/смена недели в покупках игнорирует старый ответ, сетевые ошибки снимают pending и оставляют доступный предыдущий результат с понятной актуальностью.
- [x] Проверены смешанный own/warning/broken план, изменение servings источника, удаление источника, пустые состояния и обратные ответы на разных неделях.

## Evidence

- **Единый модуль.** `WeekPlanReader` (`backend/src/MenuPlanner.Api/Plans/WeekPlanReader.cs`) — единственное чтение недели для карточки плана и списка покупок. Проекция `PlanProjection.Names` берёт только имя источника скалярно (`ExternalRecipeSourceLoader.LoadSummariesAsync`, без `RecipeSteps`/`RecipeIngredients`), `PlanProjection.Ingredients` — только ингредиенты и порции (`LoadIngredientSourcesAsync`, без шагов). Возвращается `WeekPlanContent`/`PlanContentEntry` с разрешённым `State` и живым `Content`; потребители не собирают состояние сами. Наличие живого источника — один факт, определяющий и имя, и контент, и `Broken`: исчезнувший между чтениями источник не теряет запись молча.
- **Список покупок.** `ShoppingListContentBuilder.Build` (`backend/src/MenuPlanner.Api/ShoppingList/ShoppingListContentBuilder.cs`) — чистая функция: масштабирует живые ингредиенты (`ShoppingListBuilder.Scale`, правила `ShoppingListBuilder`/группировки не тронуты), записи со `State == Broken` исключает из сумм и возвращает в `ExcludedPlanEntry` (день, приём пищи, рецепт, причина `source_missing`); устаревшие ингредиенты обёртки не читаются. `ShoppingListEndpoints` стал тонким: `ReadContentAsync` → `Build` → DTO.
- **Контракт.** `ShoppingListDto` расширен обратно-совместимо: `hasPlan` отличает отсутствующий план (`false`) от пустого/только-недоступного (`true`), `excluded` — диагностика полноты. Изменение зафиксировано в `README.md` (карта API и отличие состояний) и `CONTEXT.md` («Контент недели», «Диагностика полноты списка покупок», stateless-классификация `ShoppingListContentBuilder`).
- **Frontend.** `useShoppingList` (`frontend/src/composables/useShoppingList.js`): номер запроса и запрошенная неделя гасят поздний ответ другой недели; сетевая ошибка снимает pending, но оставляет предыдущий результат, а `resultWeek`/`resultIsCurrent`/`resultWeekDate` показывают, за какую неделю он показан. `ShoppingView.vue` показывает предупреждение «Список неполный» с перечнем исключённых записей (день · приём пищи — блюдо, причина) и ссылкой на план недели; различает «план не составлен», «в плане нет блюд» и «только недоступные». `PlanView.vue` принимает `?week=` (переход из покупок открывает нужную неделю для замены/удаления).
