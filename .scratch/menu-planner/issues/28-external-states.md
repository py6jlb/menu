# 28: Состояния «отозвана» и «сломана»

**What to build:** Получатель видит предупреждение, если ссылка, по которой он добавил рецепт, отозвана или перегенерирована (источник жив) — с кнопкой «Сделать копию, чтобы сохранить». Если семья-источник удалила рецепт, обёртка становится «сломанной»: имя-кэш остаётся, контент недоступен, рецепт исключается из списка покупок, в плане недели помечен «недоступно» с действием «убрать или заменить».

**Blocked by:** 27 (Добавление внешнего рецепта в свою семью)

**Status:** resolved (commit 6521aa4)

- [x] Единое правило состояния: `warning` если `SourceToken` обёртки ≠ актуальному токену `RecipeShare` или шеринг отозван; `broken` если источник удалён; иначе `ok`
- [x] Отзыв/перегенерация источника → у получателя `warning`: баннер на детальной странице, бейдж в списке, пометка в плане, CTA «Сделать копию, чтобы сохранить»
- [x] Удаление рецепта-источника → у получателя `broken`: имя-кэш остаётся, контент недоступен, бейдж «недоступно», из списка покупок исключена, в плане «убрать или заменить»
- [x] Участник может убрать «сломанный»/внешний рецепт из своей семьи локально (источник не затрагивается)
- [x] Flow-тесты через `ApiFactory` покрывают отзыв → warning и удаление источника → broken; юнит-тесты правила состояния (rule: `SourceToken ≠ токен`/отозван/источник удалён)

**Deferred (tickets 29/30):** бэкенд `POST /api/recipes/{id}/copy` не реализован — CTA «Сделать копию, чтобы сохранить» на фронте уже вызывает `copyRecipe`, но станет рабочим в тикете 29. Живые ингредиенты внешних рецептов в списке покупок, автодополнение, повторяемость и подбор — тикет 30; здесь только исключение `broken` из закупки.
