# 61: Подбор доступных блюд с актуальными фильтрами и поиском

**What to build:** Пользователь выбирает доступное блюдо по текущим фильтрам и поиску: сломанный источник не предлагается как пригодный, отозванная ссылка остаётся доступной с пояснением, выбранное имя и состояние не теряются при изменении выдачи.

**Blocked by:** 60 — Единое актуальное чтение рецепта для списка и деталей.

**Status:** ready-for-agent

- [ ] Подбор использует единое чтение актуального контента; broken исключён из доступной выдачи и не может быть подтверждён как доступное блюдо.
- [ ] Warning остаётся доступным по ADR; результат передаёт достаточно metadata состояния/происхождения и не маскирует внешний рецепт под обычный.
- [ ] Выбор хранится отдельно от текущей выдачи; исчезновение выбранного рецепта из нового фильтра не создаёт запись с пустым именем или неявно другим состоянием.
- [ ] Изменение только порций сохраняет актуальное имя/state записи; перед подтверждением недоступного выбора пользователь получает объяснение.
- [ ] Черновые и применённые фильтры согласованы; «Сбросить» действительно получает выдачу без фильтров, поздний ответ не заменяет более новый.
- [ ] Поиск имени выполняется на сервере до ограничения результата, с ограниченной выдачей и стабильным порядком; рецепт вне первой сотни находится поиском.
- [ ] Ошибка подбора показана рядом с операцией, pending завершается, существующий план/выбор не очищаются.
- [ ] Проверены broken/warning, фильтрация выбранного рецепта, сброс, обратные ответы, более 100 рецептов и сохранение metadata при изменении порций.
- [ ] Чистые правила жёстких фильтров и мягких предпочтений сохранены; расчёт повторяемости добавляется отдельным тикетом.
