# 54: Черновик рецепта с правильной идентичностью и защитой от потери

**What to build:** Пользователь создаёт и редактирует рецепт без риска отправить содержимое одного рецепта в другой; переходы, сетевые ошибки и поздние ответы не теряют или подменяют введённые данные.

**Blocked by:** None (can start immediately)

**Status:** resolved (ticket/54-identity-safe-recipe-draft; commit e220f48)

- [x] Identity редактируемого ресурса, загруженный snapshot и черновик связаны; ID для сохранения фиксируется вместе с отправляемыми данными.
- [x] Изменение ID рецепта, переход edit → new и смена токена публичной ссылки инициируют корректный lifecycle загрузки, даже при переиспользовании экземпляра маршрута.
- [x] Поздний ответ старого рецепта/токена не заменяет новое содержимое; фото, ошибки, sharing-состояние и значения формы не переносятся между ресурсами.
- [x] Dirty учитывает поля, порядок ингредиентов/шагов, выбранное/удалённое фото; первоначальная загрузка не считается правкой.
- [x] Уход, Back, refresh, отмена и выход предупреждают о потере изменений; отказ сохраняет пользователя и черновик на месте.
- [x] Загрузка и сохранение завершают pending при network/timeout/parsing failures, сохраняют введённое и дают понятный повтор; старая мутация не очищает более новый черновик.
- [x] Подробная и публичная страницы также показывают ресурс, соответствующий текущему маршруту, и корректно восстанавливаются после сетевого отказа.
- [x] Поведенческие проверки воспроизводят A/edit → B/edit, edit → new, смену share-token, обратный порядок ответов, отмену ухода и сбой загрузки/сохранения.

## Evidence

- Identity-безопасный черновик вынесен в `frontend/src/composables/useRecipeDraft.js`: `editingId` + `draft` + `confirmedSnapshot`, каждая загрузка/мутация привязана к identity и номеру запроса; `setIdentity` сбрасывает черновик и обесценивает in-flight запросы прежнего ресурса. ID для сохранения фиксируется до `await` вместе с телом запроса.
- Загрузка ресурса по ключу маршрута — `frontend/src/composables/useRouteResource.js`: поздний ответ старого id/token игнорируется, ресурс очищается при смене ключа, есть `reload()` для повтора после сетевого отказа.
- `RecipeFormView.vue` использует `useRecipeDraft`; `watch` на `route.params.id` перезапускает lifecycle при смене id и edit → new; `onBeforeRouteUpdate`/`onBeforeRouteLeave` и `beforeunload` предупреждают об уходе (Back/refresh/выход через `window.location.href` в `App.vue`), «Отмена» идёт через тот же guard.
- `RecipeDetailView.vue` и `SharedRecipeView.vue` переведены на `useRouteResource`, сбрасывают per-resource состояние (share, ошибки, копирование) при смене id/token, guard-ят асинхронные действия по захваченному id и показывают «Повторить» после сетевого отказа.
- Dirty учитывает значения полей, порядок ингредиентов/шагов, выбранное/удалённое фото; пустые шаги/строки игнорируются как при сохранении, поэтому первичная загрузка не создаёт ложный dirty.
- Тесты: `frontend/src/composables/useRecipeDraft.test.js` (23 теста) и `frontend/src/composables/useRouteResource.test.js` (5 тестов) — A/edit → B/edit, edit → new, смена share-token, обратный порядок ответов, утечка фото/ошибок, dirty (поля/порядок/фото), правка во время PUT, старая мутация не чистит новый черновик, отмена ухода, network/parsing/HTTP сбои.
- Команды: `docker run --rm -u "$(id -u):$(id -g)" ... node:24-alpine sh -c "npm ci && npm test && npm run build"` — 43 passed (3 файла), build успешно.
- Ограничение: тайм-аут HTTP реализуется на уровне `fetch`; любое отклонение промиса (в т.ч. таймаут) обрабатывается общим `catch`, автоматического повтора нет — пользователь видит сообщение и кнопку «Повторить».
