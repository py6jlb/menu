# 54: Черновик рецепта с правильной идентичностью и защитой от потери

**What to build:** Пользователь создаёт и редактирует рецепт без риска отправить содержимое одного рецепта в другой; переходы, сетевые ошибки и поздние ответы не теряют или подменяют введённые данные.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Identity редактируемого ресурса, загруженный snapshot и черновик связаны; ID для сохранения фиксируется вместе с отправляемыми данными.
- [ ] Изменение ID рецепта, переход edit → new и смена токена публичной ссылки инициируют корректный lifecycle загрузки, даже при переиспользовании экземпляра маршрута.
- [ ] Поздний ответ старого рецепта/токена не заменяет новое содержимое; фото, ошибки, sharing-состояние и значения формы не переносятся между ресурсами.
- [ ] Dirty учитывает поля, порядок ингредиентов/шагов, выбранное/удалённое фото; первоначальная загрузка не считается правкой.
- [ ] Уход, Back, refresh, отмена и выход предупреждают о потере изменений; отказ сохраняет пользователя и черновик на месте.
- [ ] Загрузка и сохранение завершают pending при network/timeout/parsing failures, сохраняют введённое и дают понятный повтор; старая мутация не очищает более новый черновик.
- [ ] Подробная и публичная страницы также показывают ресурс, соответствующий текущему маршруту, и корректно восстанавливаются после сетевого отказа.
- [ ] Поведенческие проверки воспроизводят A/edit → B/edit, edit → new, смену share-token, обратный порядок ответов, отмену ухода и сбой загрузки/сохранения.
