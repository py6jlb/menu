# 59: Согласованная сессия и понятные ограничения действий

**What to build:** Пользователь видит актуальную сессию и полномочия на всех вкладках, продолжает открытие рецепта после входа и понимает ограничения неподтверждённой почты. Старый запрос не завершает новую сессию.

**Blocked by:** None (can start immediately)

**Status:** resolved (ticket/59-consistent-session-lifecycle; commits 283cd4c, 692adc1)

- [x] Инициализация сессии имеет явное состояние; защищённая навигация учитывает результат актуального me, а не окончательно решает доступ по устаревшему cache.
- [x] Подтверждение почты и выход в другой вкладке отражаются в текущей; синхронизация не запускает бесконечные запросы/перезаписи storage.
- [x] 401 очищает только ту сессию, токен которой использовал запрос; поздний 401 прежнего токена не удаляет новую сессию.
- [x] Ошибки чтения/записи или отсутствие storage не дают белого экрана; предусмотрено согласованное поведение сессии в текущей вкладке.
- [x] Admin отображается как Администратор, User — Пользователь; владение семьёй определяется отдельно, роль Admin не названа Владельцем семьи.
- [x] Импорт внешнего рецепта, промоушен, локальное удаление и прочие запрещённые мутации для неподтверждённой почты скрыты/недоступны с понятным переходом к подтверждению.
- [x] Вход/регистрация из ссылки на рецепт возвращают к исходному внутреннему маршруту; внешний или некорректный returnTo не создаёт открытый redirect.
- [x] Login/register/forgot/reset/verify/admin корректно снимают pending при сетевых ошибках и сохраняют пригодные для повтора поля.
- [x] Проверены инициализация со старым cache, две вкладки, старый 401 после нового входа, недоступный storage и продолжение импорта по ссылке.
