# PDF-документ рецепта

Рецепт может нести необязательный PDF-документ (`Recipe.DocumentPath`) — готовое описание, которое пользователь приложил вместо ручного ввода. Документ сосуществует с фото, хранится отдельно от него (каталог/том `documents`, `DOCUMENTS_DIR`) и отдаётся анонимно по неугадываемому имени (`/api/documents/{file}`, `application/pdf`, inline) — как фото, потому что так работает публичный просмотр по ссылке. Один документ на рецепт.

Шаги приготовления стали необязательными: метод может быть в описании рецепта или в приложенном PDF. Обязательно только название; время, порции и сложность остаются обязательными, потому что по ним работает подбор. PDF-рецепт полноценно участвует в плане и подборе; в список покупок он ничего не добавляет — как и любой рецепт без ингредиентов, молча.

Документ едет от источника у внешнего рецепта, копируется при промоушене в копию и виден в анонимном просмотре по ссылке; файл проверяется по сигнатуре `%PDF-` и ограничен 20 МБ. Выбрали отдельный файловый слой и вложение, а не обязательный структурированный ввод, потому что пользователю нужен быстрый путь для готовых документов, а расчёт ингредиентов для таких рецептов и не предполагается.
