# Схема БД ведётся EF Core миграциями

`EnsureCreated` заменён на EF Core миграции. При старте backend применяет `MigrateAsync` (только для relational-провайдера), без флагов окружения и ретраев: ошибка миграции роняет процесс (fail-fast), а готовность Postgres к моменту старта гарантирует `depends_on: service_healthy` в compose. Одна `Initial`-миграция фиксирует текущую модель; локальный манифест `.config/dotnet-tools.json` прибивает `dotnet-ef`, а `deploy/build-push.sh` падает на `has-pending-model-changes`, если модель и миграции разошлись.

Миграции пишутся только вперёд: down-миграции не поддерживаются, и откат версии приложения не откатывает схему. Откат — восстановление БД из бэкапа (см. ADR-0006) вместе с деплоем прежнего образа: сначала данные, затем код.

Тесты остаются на EF InMemory: гард `IsRelational()` пропускает миграции, реальная Postgres в тестах не поднимается. Цена — миграции и Postgres-специфика (например, частичный индекс) не проверяются тестами напрямую; от рассинхрона модели и миграций страхует drift-guard в сборке.
